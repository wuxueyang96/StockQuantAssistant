# 国金全量 QMT：只读 Python 策略适配

## 交付边界

这是一套 **QMT 内置策略入口 + 同机分析进程**，不是把现代 Python 项目强行导入 QMT，也不是 MiniQMT / xtquant 脚本。保留原项目趋势、MACD 结构、九转序列及三层整合算法，没有另写简化替代指标。

- `qmt/stockquant_strategy.py`：粘贴到全量 QMT 的 Python 策略编辑器，提供 `init` / `handlebar`，只用 Python 3.6 标准库。
- `app/qmt_bridge.py`：在同一台 Windows 电脑的现代 Python 环境运行，直接调用原项目 `build_daily_trading_plan` 和 `resample_ohlcv`。
- **没有任何委托、撤单、账户查询或成交接口**。只在策略日志输出分析结果，不生成交易订单，也不构成带成交净值的 QMT 回测。
- 不需要设置交易账号，不需要将仓位、资金或凭据发到远端。HTTP 仅绑定 `127.0.0.1:8765`，临时随机令牌校验，不启用代理，不提供远程监听选项。

官方文档描述内置 Python 为 3.6，而本项目要求 Python ≥3.10、pandas ≥2.2，并使用 dataclasses 等。双进程是保留原算法的兼容方案。**本次没有在国金 QMT 终端实测，不能宣称导入即可运行或单文件移植完成。** 如果必须完全单进程内置运行，需要另做原算法兼容迁移及旧 pandas 的数值对照验证。

## 启动步骤

1. 在 Windows 上准备本项目要求的现代 Python 环境及依赖。不要将项目依赖安装进 QMT 自带 Python。常规方式是在项目目录创建独立虚拟环境，然后按 `requirements.txt` 安装。
2. 项目根目录运行：

   ```powershell
   python -m app.qmt_bridge
   ```

   保持此窗口打开。复制启动时输出的临时 `BRIDGE_TOKEN`。每次重启进程令牌都会变化；它只用于本机连接，不能作为账户凭据使用。
3. 在国金全量 QMT 新建 Python 策略，将 `qmt/stockquant_strategy.py` 的完整内容粘入编辑器。设置 `SYMBOL`（例如 `600000.SH`）、`HISTORY_START`、`BRIDGE_TOKEN`。适配器是 ASCII 源码，避免 UTF-8 / GBK 编辑器差异。
4. 在 QMT 数据管理准备上证指数 `000001.SH` 日线，用于校验最近交易日；同时下载该股票从 `HISTORY_START` 开始的 **5 分钟本地历史数据**。启动模型之前至少准备 91 个完整交易日（90 日长趋势窗口加前值）。固定起点影响 EMA 初始化，比较结果时使用相同历史起点和行情。
5. 选择相应股票作为主图品种，建议日线周期，先用历史回放或模拟信号模式验证；无需交易账号。历史回调会逐日分析，数据越长计算越慢。确认本机防火墙/终端允许 Python 策略访问该 loopback 地址；不应开放公网端口。
6. 日志应显示 `status: ok`、`read_only: true`、`last_bar` 和 `plan`。否则先解决具体的数据或连接错误。服务未启动、令牌错误、缺少行情、算法错误均不会产生替代信号。

## 数据与时间约定

- 数据源是 `ContextInfo.get_market_data_ex`，`period='5m'`、`subscribe=False`、`fill_data=False`、`dividend_type='none'`。没有自动下载、订阅或跨网络补数据。
- 以 `get_bar_timetag(barpos)` 的毫秒时间戳转换为北京时间；**不用电脑当前时间决定历史边界**。
- 为避免运行中日线尚未收盘，任何回调都只分析该回调日期之前的行情，截止前一自然日 15:00。周一自然会使用上周五数据。不会在当天 15:00 提前假定最后一笔已经完成；因此日终结果在下一交易日回调才出现。
- QMT 请求与本地分析进程均按截止时间截断，防止行情接口意外返回未来数据。
- 支持沪深 A 股连续竞价的收盘时间标签：09:35–11:30、13:05–15:00，每日 48 根。缺失、重复、额外集合竞价柱、非标准时间、非法价格、NaN 都拒绝分析；不会补成假行情。整日停牌无数据不算缺柱。若国金版本使用不同时间标签，应先验证并显式适配，不要跳过检查。
- 原算法用 K 线序号合成 60/90/120 分钟，保留 90 分钟尾柱的 partial 标记及原有过滤规则。
- 使用不复权数据避免前复权数据对历史产生后见修改，但分红、拆股会造成价格跳变。结果必须结合除权除息检查，不能将原始跨除权信号当作投资结论。
- 使用 `get_trading_dates('000001.SH', '', 截止日期, 1, '1d')` 核对最近完整交易日。股票末日不匹配（包括最近整日停牌）时拒绝输出，不将旧计划标为成功；日历缺失、返回未来日期或滞后超过 15 个自然日也拒绝。该日历依赖终端指数数据，请保持指数日线更新，不能以个股缓存自身作为新鲜度证明。

## 输出含义与限制

本入口直接调用 `build_daily_trading_plan`，不走 Web/API 的 `summary_integrated` 前一计划携带仓位包装，因此不声称与界面/API 的仓位代理、文案逐字段一致。离线精确对照指的是同一输入下与原始 planner 一致。

原始计划内容保持原算法格式：`trend`、`structure`、`sequence`、`decision` 等。0–10 是原算法仓位档位，不是股数或账户百分比。

**没有读取实际持仓**。原算法在未传持仓时以此前趋势仓位（或零）作为 `actual_position` 代理。外层 `position_source` 明确标识该来源，不能将 `order_delta` / `action` 当作真实账户指令。`execute_date` 仍是原项目按工作日估算的日期，不是交易所节假日日历。

本适配保留原算法既有语义和限制；不以此次改造证明算法盈利或修复所有既有逻辑问题。更改固定历史起点、行情源、复权方式都会改变结果。多股票池、持仓接入、自动交易、实时分钟内策略与绩效回测不在此版本范围。

## 离线验证

```bash
python -m pytest tests/test_qmt_bridge.py -q
```

覆盖：原算法计划精确对照、未来数据截断、缺柱/重复/非法价格/不足预热拒绝、Python 3.6 语法解析、stdlib-only 入口、无交易调用、回调截止时间、成功去重与失败重试限频。

Python 3.6 语法解析不等于在 Python 3.6/国金终端执行通过。尚需在用户实际版本验证 API 签名、索引标签、缓存更新时间、loopback 通信及旧解释器运行时。
